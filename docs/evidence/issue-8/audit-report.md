## Shared UI and position review

Source review finds the central Back callback orders annotation dismissal, nested/root book note Back, lookup dismissal, preview cancellation, native selection dismissal, controls, fixture screen and exit. Compose dialogs can consume Back first. This is a policy hypothesis; actual permitted combinations must be recorded on Android. Back never calls slider Return. The shared registry exposes Dictionary lookup, Highlight and Annotation note using the original selection. Native selection recreation can retrigger lookup and reset the chosen source, as #3 observed.

Committed locator, transient preview, per-book Return and note navigation are separate app state. Room saves slider destination/Return atomically. Ordinary committed navigation leaves Return unchanged. The #7 read-only races around pending persistence, cancel input and typography are fixed in source, but their exact interleavings lack runtime reproduction. No extra pass follows from review.

Resume and reflow use paragraph/block selectors plus text/progression. A saved block can appear lower on the restored page. No exact first-character fidelity is demonstrated. #7 measured native `navigator.go` target/selector problems; final integration calls pinned Readium JavaScript `readium.scrollToPosition` / `readium.scrollToLocator` and verifies viewport geometry/selector intersection. This workaround is coupled to 3.1.2 and needs rerunning on upgrades. Its existence is not a universal engine guarantee. The earlier selector failure has no preserved raw timeout log, so do not fabricate one.

The earlier 5-book migration and later 4-book epochs differ without a recorded app deletion. Host emulator exit and transient package probe are not proof of app data loss or proof of app correctness. Preserve this discrepancy. Snapshot current data at the start and finish of combined testing; never reinterpret old captures as one continuous session.
